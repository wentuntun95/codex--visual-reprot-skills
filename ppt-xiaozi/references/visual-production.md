# 视觉设计与正式制作

仅在内容草稿冻结后读取。正式设计可以优化层级、留白、换行和表达精度，但不能擅自改变中心观点、论据关系或数据含义；若必须改变，退回草稿确认。

## 1. 选择视觉路径

按优先级选择一种路径：

1. 用户提供参考PPT或现有正式页：完整检查参考稿，提炼并延续其视觉系统。
2. 用户给出明确视觉方向：据此设计代表性示例页。
3. 无参考页和明确方向：形成简短视觉简报，用同一张代表性草稿页探索2-3个明显不同的视觉方向，再由用户选择。

视觉方向不能只换颜色；同时改变构图、字体层级、留白、图片处理、图标、材质和数据表现。1-2页简单PPT可只提供1-2个方向，不必建立完整背景体系。

## 2. 冻结视觉系统

用一张代表性正式页确认：

- 标题、副标题、正文、关键数字和来源的层级。
- 色板、字体、页边距和间距尺度。
- 内容框、强调框、结论条、截图框和图表处理。
- 图标和图片的统一语言。
- 封面、章节过渡和正文背景；背景只提供氛围，不决定页面布局。

没有参考页时，示例页应包含标题、1-3个论据、关键数字或视觉、图片占位和页面落点，避免选择封面或极特殊页面。把确认参数写入 `.ppt-agent/style.json`，可复用背景和图标放入 `style/`。

## 3. 重建正式稿

- 以草稿中的内容、层级、顺序和大致比例为依据另建正式PPT。
- 每页设置一个视觉中心：主图、关键数字、核心对比、流程或产品界面。
- 使用少量稳定组件，但不要把所有页面做成同一种卡片网格。
- 图片负责视觉和真实证据，PPT原生文字负责准确中文与可编辑性。
- 同一语义使用同一视觉处理；不要混用不同图标体系、阴影、圆角和近似色。
- 真实产品截图优先；AI图片只用于概念或无法拍摄的场景，不伪造产品证据。
- 先解决布局和文案，再添加图标与装饰；不服务中心观点的视觉元素应删除。

## 4. 整稿节奏与验收

让强视觉页、数据页、产品页和克制的过渡页形成节奏，不要求每页都制造视觉冲击。

交付前：

- 渲染并逐页检查标题换行、裁切、重叠、溢出和图片清晰度。
- 检查字体、色值、字号、页脚、来源、图标、图表和组件的一致性。
- 检查整稿故事仍与冻结草稿一致。
- 保存最终整稿；只有需要复用或独立交付时才保存单页源文件。
