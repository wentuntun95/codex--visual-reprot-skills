# 汇报长图

以“矢量文字与框架 + 原始图片嵌入 + 高清重新渲染”制作长图。优先保证内容准确、层级清楚和重复修改后仍然清晰。

## 选择模式

根据用途选择一个模式，不要一开始就投入不必要的视觉精修：

- **快速草稿**：内容仍在讨论、用户要求先看大纲或原型。白底、单一强调色、图片占位或现成图片，快速验证文字和结构。
- **内部简约**：用于内部汇报和评审。使用固定的简约视觉系统，统一标题条、框线、图片比例和重点结论样式。
- **商用设计**：用于客户、市场和公开传播。在内容冻结后增加品牌化配色、字体层级、装饰、背景与图片调色，但继续保持文字为矢量文本。

详细规则按需读取：快速草稿或内部简约读 [references/modes.md](references/modes.md)；商用设计还要读 [references/commercial-design.md](references/commercial-design.md)。

## 不可破坏的原则

1. 业务标题、数字、说明、按钮和结论必须作为 SVG/PPT/HTML 中的真实文本排版。不要让图片生成模型生成关键文字。
2. 用户提供的截图和素材必须从原始文件重新嵌入；不要截取上一版成品长图，也不要在导出的 PNG 上继续改字。
3. 每次修改都从可编辑源文件重新导出新版本，默认保留旧版本。
4. AI 图片只负责背景、插画、装饰或需要模拟的界面视觉；包含业务文案的界面优先用矢量方式覆盖准确文字。
5. 最终交付至少包含高清 PNG 和可编辑源文件。用户需要直接修改时，可再输出可编辑 PPTX。

## 工作流

### 1. 梳理内容

先提取：主标题、核心结论、模块顺序、每模块主文案、图片路径、数据和品牌要求。内容仍在变化时，先输出精炼大纲；不要提前制作商用视觉。

### 2. 建立草稿

优先复制 [assets/draft-template.svg](assets/draft-template.svg) 作为白底起点，按内容调整高度和模块。草稿应包含真实文字、图片占位或现成图片，但不需要复杂装饰。

### 3. 嵌入图片

- 检查原图尺寸和方向，保持合理裁切，禁止拉伸变形。
- 业务截图使用原始 PNG/JPG；需要新图时单独生成，再嵌入源文件。
- 若图片内含易错业务文字，优先生成无字底图，再用矢量文本覆盖。

### 4. 视觉升级

草稿确认后再进入内部简约或商用设计。保持信息结构不变，只升级色彩、字体层级、留白、装饰和图片处理，避免视觉改造带来文案漂移。

### 5. 导出与检查

使用 [scripts/render_svg.mjs](scripts/render_svg.mjs) 从 SVG 导出 PNG，默认 2 倍尺寸。检查：

- 所有文字逐字对照用户原文；
- 没有截断、溢出、错误换行或重叠；
- 图片清晰、比例正确、没有二次截图痕迹；
- 标题、数字、结论在缩略图状态仍能识别；
- 输出尺寸适合传播渠道，必要时另存轻量版，不覆盖高清版。

## 默认交付说明

说明采用的模式、最终 PNG 路径、源文件路径、生成图片素材路径（若有），以及哪些对象可编辑。不要把临时文件作为正式交付。
